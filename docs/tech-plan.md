端侧信创办公智能体技术方案
—— 面向党政/金融/运营商政企客户的PC端Agent系统设计
1 项目概述
1.1 项目背景
当前政企客户（党政机关、金融机构、运营商）在办公场景中面临一个核心矛盾：一方面，大模型AI能显著提升办公效率，自动处理文档、会议纪要、邮件撰写等重复性工作；另一方面，信创合规要求数据不能出内网、不能上云，云端大模型API无法使用。同时，国产软硬件（飞腾/鲲鹏CPU、麒麟/统信OS）生态仍在完善中，缺乏一套成熟可用的端侧Agent解决方案。
本项目瞄准这一痛点，设计并实现一套完全跑在PC端的办公智能体系统——端侧模型完成日常办公任务，端边云协同处理复杂推理，全程数据不出本机，同时具备国产软硬件适配能力。
1.2 项目定位
一句话定位：一个跑在PC端（兼容国产CPU+国产OS）的政企办公Agent，通过多智能体协作完成"文档处理→会议纪要→公文撰写→桌面操作"的完整办公闭环，数据全程本地处理。
核心特征：
（1）端侧优先：7B量化模型本地运行，8GB内存即可部署，不依赖云端API。
（2）业务闭环：不是单点工具，而是多Agent协作完成端到端办公任务。
（3）信创适配：架构预留国产CPU（飞腾/鲲鹏）+国产OS（麒麟/统信）编译适配接口。
（4）协议标准：原生支持MCP工具协议和A2A多智能体协作协议。

2.2 业务闭环设计

2.3 闭环的技术亮点
（1）多智能体分工：每个专职Agent只做自己擅长的事，降低单Agent的复杂度和出错率。
（2）动态规划：Planner不是一次性出计划，执行过程中可以根据中间结果调整后续步骤。
（3）反思校验：Reflection Agent在关键节点（文档生成后、邮件发送前）做质量检查，拦截明显错误。
（4）记忆持久化：所有操作记录存入本地向量库，下次类似任务可以参考历史，越用越聪明。

4 核心模块详细设计
4.1 Planner Agent（规划调度器）
职责：接收用户原始指令，拆解为子任务序列，调度下游专职Agent执行。
输入：用户自然语言指令 + 可用Agent列表 + 历史记忆摘要
输出：结构化任务计划（JSON格式），包含步骤列表、每步负责的Agent、依赖关系
关键设计：
（1）计划不是一次性出完——每执行完一步，Planner根据中间结果决定下一步，支持动态调整。
（2）任务粒度控制——太粗则Agent搞不定，太细则调用开销大，控制在2-5步为最佳。
（3）失败重试——某步失败时，Planner可以换一种方式重试或降级到简化方案。
4.2 Meeting Agent（会议处理）
职责：录音转写 → 会议摘要 → 待办事项提取。
技术方案：
（1）语音转写：本地运行Whisper.cpp（tiny/base模型），CPU即可跑，不需要GPU。
（2）摘要生成：Qwen2.5-7B做长文本摘要，采用Map-Reduce策略（分段摘要再合并）。
（3）待办提取：Prompt工程 + JSON结构化输出，提取"谁、做什么、什么时候完成"。
（4）输出格式：自动生成符合政务公文规范的会议纪要模板。
4.3 Doc Agent（文档处理）
职责：Word/Excel/PPT/PDF的读取、编辑、格式转换、内容提取。
技术方案：
（1）文件读写：python-docx（Word）、openpyxl（Excel）、python-pptx（PPT）、PyMuPDF（PDF）。
（2）文档生成：根据模板自动填充内容，支持政务公文格式规范（红头文件、文号、签发人等）。
（3）RAG检索：本地向量库（Chroma/FAISS）存储企业文档，支持语义检索+引用溯源。
（4）工具封装：所有文档操作封装为MCP工具，Agent通过标准协议调用。
4.4 Email Agent（邮件处理）
职责：邮件草稿撰写、收件人查询、邮件发送。
技术方案：
（1）草稿生成：根据会议纪要/通知要求，自动生成符合公文语气的邮件正文。
（2）收件人查询：从本地通讯录（SQLite）或企业通讯录API获取收件人列表。
（3）发送方式：两种路径——简单场景直接用SMTP；需要在邮件客户端操作时交给DesktopAgent。
（4）安全检查：Reflection Agent检查收件人是否正确、附件是否齐全、有没有敏感信息泄露。
4.5 Desktop Agent（桌面操作）
职责：操作桌面应用程序，完成GUI层面的任务。
技术方案：
（1）UI树读取：参考Vercel agent-desktop的思路，通过操作系统API直接读取窗口控件树（Windows UIA / Linux AT-SPI），不依赖截图+视觉模型，省token且更精准。
（2）操作执行：模拟鼠标点击、键盘输入、窗口切换，封装为MCP工具。
（3）安全边界：白名单机制——只允许操作指定的应用（邮件客户端、文件管理器、浏览器），禁止操作系统设置和敏感目录。
（4）国产OS适配：Linux下用AT-SPI协议，对应麒麟/统信桌面环境。
4.6 Memory Bank（记忆系统）
职责：存储用户偏好、操作历史、文档索引，让Agent越用越聪明。
双层记忆结构：
（1）语义记忆：Chroma本地向量库，存储历史对话、文档片段、操作记录，支持语义检索。
（2）结构化记忆：SQLite数据库，存储用户偏好（常用联系人、文档模板、格式要求）、任务审计日志。
关键设计：记忆写入时自动去重和摘要，避免向量库膨胀；记忆召回时按相关性+时间衰减加权。
4.7 Reflection Agent（反思校验）
职责：在关键节点对Agent的输出做质量检查，拦截错误。
校验规则：
（1）格式校验：生成的文档是否符合模板格式？字段有没有缺失？
（2）逻辑校验：待办事项有没有遗漏？邮件收件人对不对？
（3）安全校验：有没有敏感信息泄露？有没有越权操作？
（4）纠错机制：校验不通过时，自动生成纠错指令，让对应Agent重新生成。

10.3 路线图（体现你有规模化复制思维）
阶段1（MVP，2周）：单Agent + 文档问答 + 会议纪要提取，跑通核心链路。
阶段2（完整闭环，2周）：加多Agent编排 + 反思机制 + 记忆系统 + 桌面操作。
阶段3（国产适配，1周）：ARM编译验证 + 麒麟OS适配文档 + 性能调优。
阶段4（规模化复制思路）：插件化工具市场——ISV可以开发行业插件（金融报表、运营商工单），Agent框架本身不变，插插件就能适配新行业。这个思路直接对应JD中"联合ISV端到端推动智能体从0到1上线并规模化复制"。
